# JobAgent — 50 Sequential Build Prompts

Project: TypeScript / Node.js / PostgreSQL / Redis / BullMQ
Reference: jobagent-orchestrator-architecture.md
Convention: One prompt per feature. Each prompt is self-contained and references the output of the previous prompt. Build in strict order. After each prompt, confirm TypeScript compiles cleanly before proceeding.

19. DedupAgent
    Create agents/dedup.agent.ts. The DedupAgent takes the list of newly upserted postings from the DiscoveryAgent output and deduplicates them. A canonical key is computed as lowercase(company) + '|' + normalize_title(role_title) + '|' + normalize_location(location) where normalize_title strips seniority prefixes (Senior, Junior, Lead, Staff) and common suffixes (Engineer, Developer), and normalize_location collapses 'Remote', 'Anywhere', 'USA Remote' to 'remote'. Use pg-trgm (add extension via migration) for fuzzy matching: if two postings have canonical_key Jaro-Winkler similarity above 0.92, treat as duplicate. Keep the one with the more complete data (longer description, known apply_method). Mark duplicates in the database with a canonical_posting_id foreign key column (add via migration). Return a summary: total_input, total_unique, total_merged. Register in the agent registry.

20. AuthenticityVerifier Agent
    Create agents/authenticity.agent.ts. For each posting discovered in this run, apply hard authenticity checks in sequence. Flag as 'scam' if: the posting description contains phrases about upfront fees, equipment purchases, sending money, wiring funds, or paying for training; the company domain cannot be resolved (use dns.lookup); the apply_url is a Gmail, Yahoo, or Hotmail address; comp_range max is more than 3x typical for the role (use a hard-coded sanity table by seniority). Flag as 'suspicious' if: the company has no LinkedIn presence (call a function that checks if the company domain redirects or is very new — use a whois-node package); the same exact description appears under 3+ different company names (check via description hash across postings table). Flag as 'verified' if: company domain resolves, and either the posting's apply_url is on the company's own domain or the apply_method is 'greenhouse_api', 'lever_api', or 'ashby_api'. Write the authenticity status and signals to the postings table. Register in the registry.

22. MatchingAgent — Scoring Engine
    Create agents/matching.agent.ts. For each verified or suspicious (not 'scam') posting from this run, compute a match score against the user's profile. The score is a weighted sum (weights from pipeline.yaml config): role_match (embedding cosine similarity between posting and profile, computed via pgvector's <=> operator in a single SQL query across all postings), stack_match (count of profile.stack items appearing in the posting description divided by profile.stack length), seniority (exact match = 1.0, one level off = 0.5, two levels = 0), location (remote preference vs posting remote field), comp (overlap between profile.comp_band and posting.comp_range, or 0.7 default if comp not listed), company_quality (0.0 for companies in excluded_companies or excluded_industries, 1.0 otherwise, with a penalty for scam-flagged). Exclude any posting scoring below the min_score threshold (0.70 default). Keep top N (15 default). Return the top candidates with full score breakdown. Register in the registry.

23. Exclusion List Enforcement

Any posting marked 'scam' by the AuthenticityVerifier. Any posting where the work authorization requirements (parsed from description using regex patterns for 'must be authorized', 'visa sponsorship not available', 'US citizen only') conflict with the profile's work_authorization array. Log each exclusion with the reason. Append exclusion summary to the MatchingAgent's output metadata.

34. Draft Approval API

41. Playwright Submitter (Workday and Generic)

The strategy: load the posting's apply_url, detect the form type (Workday vs. generic), fill form fields with profile data and draft content at human-paced timing (random delay between 800ms and 2200ms per action, using setTimeout + Math.random()). For each field interaction: locate the field, focus it, type character by character with random 80–200ms per character delay (not type-at-once). If a CAPTCHA is detected (check for class names containing 'captcha', 'recaptcha', 'hcaptcha', or iframes from known CAPTCHA providers), immediately stop, mark draft as 'manual_required', and return.
